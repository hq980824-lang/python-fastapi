## 要点速记

### Model 升级（[[sqlalchemy-mapped-upgrade]]）
- `Column(...)` → `Mapped[X] = mapped_column(...)`，类型友好、有补全。
- 纯换写法，**表结构不变，不用迁移**。
- `Mapped[int]`=非空，`Mapped[int | None]`=可空（类型即约束）。
- 枚举 `Mapped[PostStatus]` 自动推断，省 `SQLEnum`。
- **`TYPE_CHECKING`**：解决「类型标注要 import、运行时不能 import」的循环依赖（类比 TS 的 `import type`）。

### 点赞功能（[[likes-feature]]）
- **联合唯一约束** `UniqueConstraint("user_id", "post_id")` 放 `__table_args__`（单元素元组要尾逗号）。
- **双层防重**：应用层查重（友好）+ 数据库 IntegrityError 兜底（并发安全）。
- `db.get(PostDB, id)` 查存在性；`func.count` 统计点赞数。
- 抽 `_get_like` 私有方法复用。

## 今天踩的坑（重点，多是 JS→Python 差异）

| 坑 | 教训 |
| --- | --- |
| `where(A and B)` 条件被吃 | SQLAlchemy 多条件用 `and_(A,B)` 或逗号，**别用 Python `and`** |
| `(UniqueConstraint(...))` 不是元组 | 单元素元组要尾逗号 `(...,)` |
| 422 错误 | `BaseModel + Depends()` 把字段当查询参数；身份信息从 current_user 来不让前端传 |
| service 用了 `CurrentUser` | service 是业务层，只收 `user_id: int`，不依赖 HTTP 概念 |
| `from ntpath import exists` | 编辑器乱加的垃圾 import，警惕诡异来源 |
| `import datetime` vs `from datetime import datetime` | `Mapped[datetime]` 要的是类，用后者 |
| 两个 MySQL 容器横跳 | 删掉手动容器，只用 compose（已清理） |
